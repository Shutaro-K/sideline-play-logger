# sideline-play-logger

iPad Safari向けのプレー記録アプリ。Phase 1では、既存UIにIndexedDBによる1試合分の永続保存を追加しています。実行時の外部ライブラリやサーバーへの記録送信はありません。

## 使い方

- Enterで記録を保存します。全項目空欄でも保存でき、保存完了後に全入力をクリアします。
- 再読み込み・同じブラウザの再起動時に記録を復元します。初回は空表です。架空サイン照合は従来どおりです。
- 行を選択して編集し、Enterで同じ記録を上書きします。元の時刻・日時・ID・順序を保持します。
- CSV出力は全件を出力し、記録を削除しません。検索中も全件が対象です。
- PLAY LOGの「リセット」で削除します。記録がある場合はCSVファイルの端末保存・内容確認を明示的に確認した後、全削除をもう一度確認します。どちらかをキャンセルすると変更しません。
- 復元・保存・リセット中は記録操作を一時停止します。保存失敗時は入力を残して継続表示で通知します。Enterで再試行してください。復元失敗時は書き込みを停止し、「復元を再試行」を表示します。

## 保存設計

- データベース：`sideline-play-logger`、バージョン：`1`、オブジェクトストア：`plays`。
- 自動採番の`id`を主キーとして登録順を維持します。同じ秒の記録でも順番は変わりません。
- 各行は`id`, `time`（表示時刻）, `recordedAt`（ISO日時）, `down`, `distance`, `strSide`, `sign`, `formation`, `play`, `remark`を保持します。
- Formation・Playは記録時の照合結果を保存します。Signを変更する編集では再照合します。Signを変えない編集では保存済みの結果を保持します。
- トランザクションの`complete`後に一覧と入力を更新します。失敗した新規・編集・削除操作は一覧へ反映しません。
- リセットは`plays.clear()`だけを実行します。データベース全体、別のストア、localStorage、他アプリのデータを削除しません。
- CSVは既存の8列を維持し、UTF-8 BOM・CRLF・CSVエスケープを使用します。Signと保存済みFormation・Playを含みます。

## 開発・テスト

`index.html`と`storage.js`を同じ場所から配信してください。ビルドは不要です。テスト用の依存パッケージは公開アプリから読み込みません。

```sh
npm install
npx playwright install chromium webkit
npm test
BROWSER_ENGINE=webkit npm test
```

インストール済みChromeを使用する場合は`BROWSER_CHANNEL=chrome npm test`。テストはローカルHTTPサーバーと独立した一時ブラウザデータを使います。

`tests/persistence.test.cjs`は通常・空白・連続保存、復元、編集、CSV、リセットの両キャンセル・実行、読み込み中の操作防止、読み込み失敗と再試行、保存・編集・削除のトランザクション中断、キーボードと表操作、ブラウザ再起動を検証します。

## 制約と実機確認

- 保存は現在のブラウザ・サイトのオリジン単位です。別端末・別ブラウザ・別オリジンとは共有しません。同じ試合は1つのタブで操作してください。複数タブの同時編集同期は未実装です。
- Safari/iPadOSによるデータ削除やプライベートブラウズ終了時などのデータ消失は保証しません。未確定のフォーム入力は自動保存対象外です。保存エラーが出た入力は再試行に成功するまで再読み込みしないでください。
- CSVダウンロードの開始はできますが、端末への保存完了はアプリから検証しません。ファイルアプリ等でユーザーが確認してください。
- WebKit自動テストはiPad実機テストの代替ではありません。実際のiPad Safariで再読み込み・終了再起動、Remarkの日本語入力、CSVのファイル保存と内容、確認ダイアログ、横向き操作と表の拡大・縮小・スクロールを確認してください。
- GitHub Pagesへの反映はレビュー・承認後に行います。
