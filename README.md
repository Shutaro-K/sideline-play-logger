# sideline-play-logger

iPad Safari向けの単独入力プレー記録アプリ。記録・下書きの端末内保存、Q・シリーズ管理、Sign対応CSV・CWM・PP照合に対応します。実行時の外部ライブラリ、サーバーへのCSV／試合記録の送信はありません。閲覧共有・認証は未実装です。

## 入力・編集

- DN／DIST／STR／SIGNを1行で入力します。DISTはS・M・L・10・10+から任意選択し、STRへ自動移動します。S・M・Lの数値範囲はアプリで推測しません。L／Rを押すとSIGNへ移ります。
- 新規時の専用EnterはDN・DIST・STRでは次の欄へ進み、SIGN・Remark・CWM枝番では保存します。SIGNを選べば全項目空欄でも保存できます。編集中はどの欄からでも同じ行を更新します。標準キーボードのテキスト欄のEnterは改行・日本語変換に使います。
- 保存が完了してから入力をクリアします。編集中の次プレーの下書きは退避し、更新・キャンセル後に戻します。元ID・記録時刻・表示順を保持し、編集日時は別に保存します。
- IN／OUTは仮の別記入画面のままです。作り込みは保留。空欄でも保存でき、Coverageの未選択と0を区別します。
- 対応表を入れ替えても過去のFormation／Play・PPを自動変更しません。編集時もSign・入力枝番が同じなら保存済みの照合結果を保持します。

## Q・シリーズと表

- 現在Qは1・2・3・4・OT。初期値は1で、変更した値は次の新規記録から保存します。過去のQを一括変更しません。
- 表にQ列を出さず、前後の記録でQが変わる位置に二重線を表示します。Q変更ではシリーズを分割しません。旧記録にQを推測して補いません。
- Punt／FG／TD／TOは、最後に保存したプレーを確認して終了ラベルを付けます。Punt＝オレンジ、FG＝青、TD＝緑、TO＝赤で表示します。次の新規プレーから次シリーズを自動開始し、終了ラベル自体はプレーとして数えません。終了ラベルは得点などの意味に変換しません。
- 通常のiPad横向きでは短い行が7行見える配置です。長いFormation／Playは省略せず折り返し、行高を増やします。
- 表の拡大・検索・スクロール・行編集を維持します。全画面のIN／OUTチェックとRemarkを押すと吹き出しを表示し、外側・同じセル・閉じるボタン・Escで閉じられます。OUTはCoverageとメモを併記し、長文は吹き出し内でスクロールします。

## Sign対応CSV

右上の「CSV読込」からUTF-8（BOMあり・なし）を選びます。7列は次の順です。

```text
sign,formation,play,record_type,sign_raw,parent_sign,branch
```

- `sign`は先頭の0を含む半角数字5桁で一意。`formation`は空欄不可。
- `record_type`は`normal`・`cwm_parent`・`cwm_choice`。`play`は通常／子では必須、親では空欄。
- `sign_raw`は5桁または5桁(2桁)の出典表記として保持し、照合キーの推測には使用しません。
- CWM子は親Signと枝番1・2を持ち、子Signは「枝番＋親Signの後ろ4桁」と一致する必要があります。各親には子1・2が両方必要です。通常／親の`parent_sign`・`branch`は空欄です。
- ヘッダー、7列、重複、親子関係、文字コード、引用符等を検証し、保存成功後に一括適用します。不正CSV・キャンセル・保存失敗では以前の対応表を保持します。
- 引用符付きカンマ・改行・二重引用符、CRLF／LF／CRに対応します。実CSVや架空の対応表はアプリに同梱しません。

CWM親の5桁入力後に専用テンキーの1・2で枝番を選びます。「枝番」ボタンでも入力先を選べます。削除は枝番を先に消し、その後にSignを消します。子Signの5桁直接入力にも対応します。未確定は`CWM（枝番未確定）`のまま保存し、子を推測しません。未照合Signも記録できます。

## PP51・52・53・54・59

- Sign完全一致を最優先します。PPを51などへ置き換えて入力・保存する処理は行いません。
- 完全一致がない場合、通常行のPlay先頭にある`<51/52>`などの明示PP表記を根拠に、同じ先頭3桁の共通パスプレーを照合します。候補全件のFormationとPP表記を除いたPlayが一致する必要があります。
- 単一候補の場合は表記に51・52の両方が必要です。候補の矛盾、PP表記のない候補、CWMとの衝突では共通プレーを割り当てません。先頭3桁だけの照合は行いません。
- 共通照合は`pp_common`とし、Playを実入力の`<53>`などで表示・保存します。`protection`は実入力PP、`lookupSourceSign`は参照元、`resolvedSign`は空欄です。CSV完全一致の保護と誤認させず、保護ルール自体は推測しません。
- 矛盾する候補は`pp_ambiguous`としてSign・PPを保持して記録できます。通常プレーやCWMをPPの近似照合で置き換えません。

## 保存・復元

データベースは`sideline-play-logger`、バージョン3です。

- `plays`：自動採番ID順の記録。Phase 1・2からの更新でも既存行・時刻・ID・採番順を保持します。旧Distanceの数値を保持し、編集時も表示します。旧行へQ・シリーズ・観察内容を推測で付け足しません。
- `signMappings`：現在の対応表1件（`current`）。全7列と読込日時を保持します。
- `appState`：現在Q、入力途中の内容、編集対象、退避中の次プレー、IN／OUT画面を保存します。記録の追加・更新・リセットと下書きの切替を同一トランザクションで確定します。
- 復元完了まで入力・記録・CSV読込・出力・リセットを停止します。復元失敗時は停止を維持し、再試行ボタンを表示します。
- 保存はトランザクション完了後に画面へ反映します。失敗時は画面の入力を残して通知します。CSV読込でも未保存の記録入力を消しません。
- リセットはCSVを端末に保存して内容を確認したことと、全記録の削除を二段階で確認します。実行時は記録と下書きをクリアし、現在Q・対応表・他アプリの設定は保持します。

## CSV出力

検索中も全記録を出力し、出力しても削除しません。既存の12列を同じ順で維持し、8列を末尾に追加します。

```text
Time,Down,Distance,Str Side,Sign,Formation,Play,Remark,Lookup Status,Resolved Sign,Parent Sign,CWM Branch,Q,Series,Inside,Coverage,Outside,Series End,Protection,Lookup Source Sign
```

UTF-8 BOM、CRLF、CSVエスケープを維持します。`Sign`は実入力、`Resolved Sign`はCSV完全一致の通常Sign／確定子、`Parent Sign`・`CWM Branch`はCWMの照合結果です。旧ログの不足列は空欄、旧照合状態は`legacy`として出力します。

## 開発・テスト

`index.html`・`storage.js`・`sign-lookup.js`を同じ場所から配信します。ビルド・実行時の外部依存はありません。

```sh
npm install
npx playwright install chromium webkit
npm test
BROWSER_ENGINE=webkit npm test
```

インストール済みChromeは`BROWSER_CHANNEL=chrome npm test`。既存の保存・CSV・CWMのテストを維持し、変更した入力操作に合わせています。Q・シリーズ、旧DB移行、下書き・編集、保存失敗、PPの正常・異常を追加しています。ブラウザは独立したテスト用環境で、CSVや記録を外部へ送るリクエストがないことも検証します。テスト・スクリーンショットのデータは架空です。実CSVはコミットせず、`.gitignore`でも除外します。

## 制約と実機確認

- 保存は現在のブラウザ・オリジン内のみ。同じ試合は1タブで操作してください。複数タブ同時編集、認証、クラウド共有は未実装です。
- 下書きも非同期保存しますが、書込完了前の強制終了やブラウザのストレージ削除までは保証しません。保存失敗時は画面の入力を残すため再試行してください。
- IN／OUTの記入方式の最終決定、過去行のQ訂正専用UI、集計は今回の対象外です。
- iPad Safariでファイル選択、実CSV照合、再読み込み・再起動、専用Enterと日本語入力、ソフトキーボード・YouTube併用幅、端末へのCSV保存を確認してください。WebKit自動テストは実機確認の代替ではありません。
- mainへのpush・GitHub Pages反映はレビュー・承認後に行います。
